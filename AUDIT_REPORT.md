# FlipperDroid 2.1.0 — Auditoria de qualidade, falhas e oportunidades

Data: 2026-11-03 · Branch auditado: `claude/happy-franklin-wjei0n` (HEAD `1a745d4`) · ~20.300 linhas Kotlin, 48 telas, 32 ViewModels.

## 1. Resumo executivo

O projeto está funcionalmente ambicioso e bem organizado (MVVM + Compose, núcleo puro testável, princípio de "honestidade de capacidade"), mas a auditoria encontrou **problemas estruturais que afetam todos os usuários** (distribuição, crash em Android 7, dependências) e **vários módulos que prometem o que não fazem** (traceroute, fuzzer BLE, relay NFC, scanner MQTT/CoAP, sniffer). Também há **falhas de segurança/privacidade** (injeção de shell via `su`, segredos TOTP e dados de cartão em texto puro com backup habilitado, credenciais capturadas indo para o logcat e expostas por HTTP na LAN) e **bugs de protocolo reais** (rajadas IR Sony/RC5 com polaridade invertida, ONVIF bloqueado por cleartext, tecla presa no BadUSB).

## 2. Metodologia e o que foi verificado

- Leitura integral do código (eu: BLE, núcleo, build/CI; três revisores paralelos: NFC/EMV, Wi-Fi/Rede/Câmeras, IR/BadUSB/Utilitários). Cada achado de alto impacto dos revisores foi reconferido por mim no código antes de entrar aqui. Itens incertos estão marcados **(possível)**.
- Não há Android SDK no ambiente (download bloqueado). Compilei o **núcleo puro** (`camera/OnvifTools`, `flipper/*`, `infrared/*`, `security/TotpGenerator`, `reports/ReportGenerator`, `redteam/FuzzPayload`, `iot/IotProtocolScanner`, `network/PacketSniffer`, `util/AppLog`) com kotlinc 2.0.21 e rodei `LogicUnitTest` com JUnit 4.13.2: **38/38 testes passam**. Quatro testes foram excluídos por dependerem de classes Android (`ducky_keycodes`, `wifi_frequency_to_channel`, `skimmer_flags_hc05`, `mifare_hex_roundtrip`).
- Os testes passarem **não** cobre os bugs abaixo: vários asserts só checam tamanho de array (ex.: `ir_burst_*`, `ir_necext_*`, `ac_*`), e por isso o bug #7 passa nos testes.

## 3. Falhas por área

Caminhos relativos a `src/main/java/com/example/flipperdroid/`.

### 3.1 Build, CI, manifesto e distribuição

- **[Crítico] `java.time` sem desugaring** (`build.gradle.kts` não tem `isCoreLibraryDesugaringEnabled`). `NoClassDefFoundError` é `Error`, não `Exception`: os `catch (e: Exception)` não seguram. Fix: `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.x")` ou `SimpleDateFormat` como já faz `AppLog`.
- **[Crítico] Release = APK debug** (`isMinifyEnabled=false`, sem `signingConfig`, CI roda só `assembleDebug`). Fix: keystore de release via secrets (`ANDROID_KEYSTORE_BASE64`…), `assembleRelease`, R8 ligado (vai precisar de keep rules para zxing/journeyapps).
- **[Alto] Workflow reusa a tag `v2.0.0` em todo push para `main`** (`build.yml:58-73`) enquanto o app é 2.1.0; `permissions: contents: write` global; texto "Android 10+" contradiz `minSdk 24`. Fix: remover o passo e publicar só por tag.
- **[Médio] Dependências inconsistentes**: Compose BOM 2024.09.00 (Compose 1.7) + `material-icons 1.6.4` fixo; lifecycle 2.6.1 no catálogo vs 2.8.7 inline; `navigation-compose 2.8.9` + `navigation-runtime-android 2.9.0-alpha08` (alpha em produção); `core-ktx 1.10.1`; `navigation-runtime-desktop` nunca usado; `kotlin("plugin.serialization")` aplicado sem nenhum uso; `kotlinOptions` deprecado.
- **[Médio] Manifesto**: `USB_PERMISSION` não é uma permissão real; `ACCESS_NETWORK_STATE` duplicada; `READ/WRITE_EXTERNAL_STORAGE` sem `maxSdkVersion` (nada usa storage compartilhado); `<uses-feature android.hardware.usb.host />` sem `required="false"` (Play esconde o app em aparelhos sem USB host); `allowBackup=true` com `backup_rules.xml`/`data_extraction_rules.xml` vazios; `NDEF_DISCOVERED` com `mimeType="*/*"` coloca o app no chooser de **toda** tag NDEF do sistema; `ACTION_USB_DEVICE_ATTACHED` é tratado em `onNewIntent` (`Main.kt:143`) mas não há intent-filter correspondente nem `requestPermission` → o BadUSB legado é inalcançável.
- **[Médio] Casts `as BluetoothManager/WifiManager/UsbManager`** sem `as?` em `Main.kt:146`, `BluetoothViewModel.kt:113` (chamado no `onCreate` → crash na abertura em emulador/aparelho sem Bluetooth), `SkimmerDetectorViewModel.kt:94`, `HidKeyboardViewModel.kt:89`, `WifiAnalyzer/Deauther/Wardriving/EvilPortal`.
- **[Médio] `AboutScreen.kt:85` mostra "Version 1.0.0"** (real: 2.1.0). Usar `packageManager.getPackageInfo(...).versionName` ou `buildFeatures { buildConfig = true }`.
- **[Baixo] Foreground dispatch NFC**: `techListsArray = arrayOf(arrayOf(NfcA, NfcB, NfcF, NfcV))` é uma lista AND (a tag precisaria suportar as 4) — só funciona porque `TAG_DISCOVERED` está no filtro. Considerar `enableReaderMode`, que também elimina o intent "stale" (§3.2).
- **[Baixo] Docs desatualizadas**: CHANGELOG sem 2.1.0; ROADMAP cita SDK em `/home/archiznoo`; CLAUDE.md não lista ~15 módulos (Bluetooth Classic, LAN Discovery, Netcat, GPS Spoof, Crypto Tools, Wi-Fi QR, Default Creds, Tracker Detector, NDEF Emulator, Card Emulation, red team); `.github/release-v2.0.0.txt` e `assets/logs/exemple.log` são lixo versionado; `ANDROID_CAPABILITIES.md:22` marca "Relay NFC/HCE" como disponível.
- **[Baixo] i18n**: 376 `Text("…")` hardcoded, `strings.xml` com 2 entradas, UI mistura PT/FR/EN (ex.: logs do NFC em francês, "Retour" no BLE Spam).

### 3.2 NFC / EMV / Flipper

- **[Alto] Relay NFC é um stub enganoso**: `nfc/NfcRelayAttack.kt` só constrói uma lista de comandos fixos com respostas vazias e tenta abrir um socket para `127.0.0.1:6669` (nada escuta); `NfcRelayAttackViewModel.captureRelayAttack/replayCapture/exportCaptures` **não têm nenhum chamador** (Main.kt só roteia tags para `NfcViewModel` e `EmvReaderViewModel`); a tela diz "Scan an NFC card to capture" mas isso nunca acontece. Recomendação: remover o módulo (e a linha do ANDROID_CAPABILITIES) ou renomear honestamente para "sonda APDU" usando `ApduCapture`, que já existe e funciona.
- **[Alto] Dados de cartão em texto puro + backup**: `EmulationStore` guarda em `hce_emulation` as respostas de READ RECORD (que tipicamente incluem PAN/track 2/nome). Fix: excluir do backup, mascarar 5A/57/5F20 e cifrar com chave do Keystore. `EmvCardData.toString()` (`EmvCardReader.kt:349-356`) imprime o PAN completo (leak latente).
- **[Alto] Clone Ultralight/NTAG escreve config/lock/PWD/PACK** (`MifareUltralightUtils.kt:52-58` só pula páginas 0–3). Pode trancar o cartão alvo de forma irreversível. Fix: identificar o tipo via `GET_VERSION` e pular o range de configuração (NTAG213 40–44, 215 130–134, 216 226–230); escrita dessas páginas só com opt-in explícito.
- **[Alto] Duas conexões simultâneas ao mesmo tag Type-4**: `NfcViewModel.onTagScanned` abre `Ndef.connect()` em IO enquanto `Main.kt:174` dispara `EmvReaderViewModel.readCard` → `IsoDep.connect()` no mesmo `Tag` (o próprio comentário em `NfcViewModel.kt:91-93` explica por que isso falha). Fix: um coordenador único por tag (Mutex) e rotear ao EMV só tags IsoDep.
- **[Médio] Intent NFC "stale"**: `Main.kt:126` chama `handleNfcIntent(intent)` no `onCreate` sem checar `savedInstanceState`. Quando o app é lançado pelo sistema a partir de uma tag (filtro do manifesto), cada rotação reprocessa a tag; com clone armado, `performClone` roda de novo. Fix: processar só com `savedInstanceState == null` e depois `setIntent(Intent())`.
- **[Médio] Clone pode rodar 2×** (flag `_cloneArmed` só é limpa após a escrita; `pendingCloneDump` é `var` não volátil lido/escrito em threads diferentes).
- **[Médio] Dump parcial vira resultado**: sem `try` por setor, um `TagLostException` deixa `dump` desalinhado e ele é salvo no histórico/`.nfc`/MCT com setores deslocados (`NfcViewModel.kt:96-151`, `287-293`).
- **[Médio] `Ndef.close()` fora de `finally`** (`NfcViewModel.kt:175-178`, `219-229`).
- **[Médio] Export `.nfc` incorreto**: `FlipperNfc.generate` sempre escreve `Device type: Mifare Classic`, `ATQA 00 04`, `SAK 08` (4K deveria ser `18`; Ultralight/NTAG/NfcV viram "Mifare Classic"), e blocos desconhecidos saem como `-- -- --` em vez de `??` (o Flipper não carrega) **(possível, conferir com o firmware)**. `NfcInfo` já tem ATQA/SAK reais — usar.
- **[Médio] `ApduCapture`** chaveia respostas só pelo comando → colisão entre AIDs; guarda GPO mesmo com erro (`6985`). Leitor EMV ignora `61xx/6Cxx`; fallback brute-force de 100 READ RECORD por AID; `transceive` engole `IOException` e continua polling um cartão que já saiu do campo.
- **[Médio] `emv_card_service.xml` registra o AID Visa na categoria `payment`** com um serviço que responde `9000` sem FCI: se o usuário escolher o app como app de pagamento padrão, toques Visa vão para um stub. Remover o grupo `payment`.
- **[Médio] `EmvReaderViewModel.readCard`** é chamado para toda tag (Mifare/NTAG) e mostra "No EMV data" + dado antigo (não limpa `_cardData`).
- **[Baixo]** `NdefHceService` aceita qualquer AID em `00 A4 04`, status words imprecisos; `NdefHceViewModel` não valida tamanho ≤ 1022 (CC anuncia 0x0400); texto NDEF UTF-16 decodificado como UTF-8; `exportMct` rotula setores de 4K errado; `exportBin` zera blocos ilegíveis; `importMct/importBin` tiram o UID de `blocks[0].take(8)` (errado para UID de 7 bytes); helpers hex duplicados em 3 arquivos; `MifareClassicUtils.readSector/writeBlock` e `NfcVUtils.writeBlock` sem chamadores; `hexToBytes` chama `android.util.Log` (quebra testes JVM que caírem no catch); `FlipperFilesScreen` parseia `.sub` grande na main thread; nenhum aviso quando o NFC está desligado.

### 3.3 Bluetooth / BLE

- **[Alto] `BleSpamScreen` quebrada em Android 8–11**: anotada `@RequiresApi(S)` mas navegável em qualquer versão; pede `BLUETOOTH_ADVERTISE/SCAN/CONNECT` incondicionalmente → em API < 31 o sistema devolve "negado" e a tela fica presa em "Bluetooth permissions are required". As outras telas BLE já fazem a lista por versão — copiar.
- **[Alto, provável] Extended advertising mata a eficácia**: `ModernAdvertisementService.prepareAdvertisementSet` força `legacyMode=false` sempre que o chip suporta (Pixel 7 suporta). Swift Pair é definido sobre ADV_IND legacy e o Windows só recebe extended advertising com opt-in (`AllowExtendedAdvertisements` é `false` por padrão — [Microsoft Learn](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.advertisement.bluetoothleadvertisementwatcher.allowextendedadvertisements?view=winrt-26100), [publisher](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.advertisement.bluetoothleadvertisementpublisher.useextendedadvertisement?view=winrt-26100)); iOS/Android também varrem legacy para Continuity/Fast Pair ([Novelbits](https://novelbits.io/bluetooth-low-energy-advertisements-part-2/)). Precisa de teste em campo; alternativa: manter legacy para payloads ≤ 31 bytes e só usar extended quando não couber, avisando.
- **[Médio] Erros silenciados**: `onAdvertisingDataSet(status)` é ignorado → `updateAdvertisement()` devolve `true` mesmo quando o controlador rejeita (payload > 31 bytes em set legacy, troca entre set com/sem scan response no modo "ALL"); SwiftPair com nomes longos ("Microsoft Bluetooth Mouse", "Surface Ergonomic Keyboard") passa de 31 bytes em legacy.
- **[Médio] `BleSpamViewModel` sem `onCleared()`** → o Handler continua emitindo depois que a Activity morre.
- **[Alto] GATT Fuzzer**: a tela fuzz o **primeiro dispositivo pareado** (`bondedDevices.firstOrNull()`, `!!` no adapter) sem seleção (`selectedDevice` nunca usado; `device.name` sem try/catch → `SecurityException` sem `BLUETOOTH_CONNECT`); o VM escreve em loop com `delay(100)` sem esperar `onCharacteristicWrite` (a pilha só aceita 1 operação pendente → a maioria é descartada mas logada como "Wrote"); `_fuzzResults`/`BleGattFuzzResult`/`severity` nunca são preenchidos — a "detecção de vulnerabilidades em tempo real" do CHANGELOG não existe; payloads de 512/1000 bytes excedem o máximo ATT sem negociar MTU; `viewModel { BleGattFuzzerViewModel(context) }` recebe o Activity context (leak); `gatt.close()` não é chamado ao fim.
- **[Médio] Scanner (`BluetoothViewModel`)**: em API 24–30 `checkPermissions` só olha `BLUETOOTH/BLUETOOTH_ADMIN` (normais) e reporta "granted" sem localização → scan silenciosamente vazio; leituras/notificações GATT sem fila (2 cliques = 1 perdido); status de `writeCharacteristic` ignorado em API 33+.
- **[Baixo]** `AdvertisementSetQueueHandler`: `_active/advertiseNext/_callbacks/_advertisementQueueMode` mortos, `% size` sem proteção; `AdvertisementSet.validate/build` e `AdvertiseData.validate` são stubs; `HidKeyboardViewModel` cria `newCachedThreadPool()` a cada registro e usa o Activity context no `getProfileProxy`; `TrackerDetector` marca qualquer manufacturer 0x0075 como "Samsung (SmartTag?)" (todo celular/relógio Samsung); `SkimmerDetector` OUI `"20:16:"` incompleto e nome `"csr"` casa qualquer fone com chip CSR; `BluetoothClassicViewModel.hexToBytes` aceita dígitos inválidos.

### 3.4 Wi-Fi, rede e câmeras IP

- **[Crítico] Injeção em `su -c`**: `NetworkToolsViewModel.kt:469` concatena `host` e `parameters` sem validação (`1.1.1.1; reboot` roda como root); `PacketSniffer.kt:52-61` concatena filtro BPF e interface (também quebra filtros legítimos com parênteses). Fix: helper `RootShell` único com quoting argv, timeout, stderr separado, exit code e `pkill` do processo filho.
- **[Alto] ONVIF bloqueado por cleartext** (`IpCameraViewModel.kt:336-360` usa `HttpURLConnection` em `http://`; sem `usesCleartextTraffic`/`networkSecurityConfig`). Fix: `res/xml/network_security_config.xml` com `cleartextTrafficPermitted="true"` (não dá para restringir por CIDR; documentar).
- **[Alto] WS-Discovery com namespace errado**: `OnvifTools.kt:56` usa `xmlns:dn="…/ver10/device/wsdl"` para `dn:NetworkVideoTransmitter`; a spec usa `…/ver10/network/wsdl` — câmeras conformes podem ignorar o probe. O teste existente só checa `contains("NetworkVideoTransmitter")`.
- **[Alto] Netcat HTTP** expõe a raiz do diretório externo do app sem auth em 0.0.0.0; `readBytes()` de arquivo grande → OOM mata o processo; checagem de path aceita diretórios-irmãos (`startsWith` sem separador); listagem HTML sem escape.
- **[Alto] Evil Portal**: `CharArray(contentLength)` dimensionado por header do cliente (OOM → `Error` não capturado → mata o app); servidor single-thread sem `soTimeout` (um cliente mudo trava tudo); credenciais capturadas vão para `AppLog` → logcat + export de logs em `getExternalFilesDir("logs")` (servido pelo Netcat); race em stop/start deixa a porta 8080 presa; falha do servidor é sobrescrita por "Hotspot up"; `onStopped` do hotspot não tratado; escuta em todas as interfaces; gateway `192.168.49.1` hardcoded.
- **[Alto] Resultados fabricados**: "traceroute" é só connect TCP em portas fixas rotulando o endereço **local** como hop (`:385`) e reporta `127.0.0.1 [ACCESSIBLE]` em qualquer exceção (`:355-357`); MQTT topic scan devolve a lista `topics` que nunca é preenchida (`IotProtocolScanner.kt:140-182`); CoAP anexa o path como bytes crus sem opção Uri-Path e conta qualquer resposta como "found"; sniffer parseia `tcpdump -A` pegando `source="IP"` e contando linhas de payload como pacotes; tcpdump ausente → "Capture complete: 0 packets" (stderr/exit code ignorados; tcpdump nem é empacotado); deauth loga "burst sent" ignorando o exit code e o watchdog mata só o wrapper `su`, não o `mdk4`.
- **[Alto] nmap**: timeout de 30 s é código morto (`waitFor()` sem timeout, `:503-516`); recopia 11 MB de assets a cada scan; `chmod -R 755 /data/local/tmp` altera arquivos de outros apps; erro de cópia vira "nmap binary not found"; em aparelho sem root `su` ausente é reportado como "binary not found"; DNS fixo 8.8.8.8; **(possível)** faltam `nmap-services`/`nmap-service-probes`/`nmap-os-db` nos assets → `-sV/-O` vazios; licença do Nmap restringe redistribuição — conferir.
- **[Médio]** Port scan 1–65535 sem cap/cancel (~7 h em portas filtradas); `isReachable` não é ICMP sem privilégio; `/proc/net/arp` restrito desde Android 10 **(possível)** → tabela vazia sem aviso; `setWifiEnabled` é no-op em API 29+; `WifiDeautherViewModel.kt:131` guarda o **Activity** context (leak, VM vive na Activity); `WifiDeautherScreen` anotada `@RequiresApi(S)` sem guarda → erro de lint NewApi; 6 GHz vira "5 GHz" com canal 0 (3 cópias de `frequencyToChannel`); MAC spoof deixa a interface down se `ip link set address` falhar; wardriving sobrescreve `firstSeen` e itera `LinkedHashMap` de outra thread no export (CME); IoT "Stop" não cancela o job; parser de range aceita `a.b.c.0/24` como string literal; GPS spoof aceita coordenadas inválidas e só afeta o provider de plataforma (não o Fused); PTZ `ContinuousMove` sem timeout/auto-stop ao sair da tela; RTSP "OPEN (no auth)" inferido só de OPTIONS; `NEARBY_WIFI_DEVICES` com `neverForLocation` pode filtrar SSID/BSSID em Android 13+ **(possível)**; detecção WPA3 só por literal "WPA3" (SAE/OWE caem em WPA2/OPEN).
- **[Baixo]** `_results.value = _results.value + …` sem `update{}` em vários VMs; quoting CSV Wigle/sniffer incompleto; sockets não fechados em `finally` (traceroute, SSDP, WS-Discovery); banner grab manda HTTP puro na 443; NSD deprecado em 34; `soapFaultReason` dá falso positivo em qualquer texto "Fault" e perde `<Text xml:lang>`.

### 3.5 Infravermelho e ar-condicionado

- **[Alto] Polaridade das rajadas** (`IrProtocols.encodePowerBurst`): o gap é `out.add(gapUs)` como elemento extra, assumindo que a trama termina em mark. SIRC **sempre** termina em space (`sirc()` termina com `600`), e RC5 termina em space quando o último bit é 0 → o gap vira mark e as repetições saem invertidas. Afeta Sony no TV-B-Gone/`PowerCodes` e Philips RC5 power; mesmo risco em rajadas `raw` com contagem par (`IrFile.kt:37-40`). Fix: se `frame.size % 2 == 0`, somar o gap ao último elemento. Teste: assertar alternância mark/space em toda rajada.
- **[Alto] "Sent" sem emissor**: `irManager?.transmit()` é no-op com `irManager == null` e o status diz "Sent" (`IrRemoteViewModel.kt:110-112`, `IrToolsViewModel.kt:68-72,145-150`, `AcControlViewModel.kt:33-35`). Checar `hasIrEmitter()` e reportar falha.
- **[Alto] Power sweep do IrRemote** não deduplica (LG e TCL usam NEC 04/08 → mesmo toggle 2× = cancela) e pega `Power_on`+`Power_off` do Epson; envia tramas isoladas que o próprio código documenta como "filtradas como ruído".
- **[Médio] AC**: swing oferecido para todas as marcas mas ignorado por LG/Coolix/Midea/Samsung; Midea `MODE_FAN → 0x4` (= DRY), Coolix FAN cai em AUTO; checksum Samsung é "aproximação" autodeclarada sem aviso na UI; rótulo "Gree VALIDÉ" se apoia num teste que só checa tamanho.
- **[Médio]** `IrFile.parseRaw` descarta tokens inválidos silenciosamente (desloca pares mark/space) e aceita 0/negativos; brute-force com protocolo desconhecido não emite mas mostra progresso; `addressHex.toIntOrNull(16) ?: 0` transforma "0x04" em 0; import de pasta IRDB parseia tudo na main thread (ANR); botões hold-to-repeat com `onClick = {}` (inacessíveis via TalkBack); race em `_running` (2 toques = 2 sweeps).
- **[Baixo]** RC6X aliasado a RC6 modo 0; endereço NEC truncado a 8 bits; toggle RC5 fixo em 0; encoder Apple ignora o campo address do `.ir`; `AC_Coolix.ir` "Turbo" e "Led" com o mesmo comando; `AcProtocols` duplica o Coolix de `IrProtocols`.

### 3.6 BadUSB

- **[Alto] BadUSB legado (USB host) não pode injetar teclas**: escreve relatórios HID via `bulkTransfer` para um endpoint OUT de um dispositivo HID conectado — o celular é o host, não o teclado. A UI diz "Connected as USB Keyboard" e "Ready to execute keyboard commands"; resultados de `bulkTransfer` e `claimInterface` são ignorados; `isUsbHostAvailable = usbManager != null` não testa `FEATURE_USB_HOST`; e o caminho é inalcançável (ver manifesto). Recomendação: remover ou rotular como experimento.
- **[Alto] Gadget root — tecla presa**: `sendKey` faz press → `delay(5)` → release; `stop()` cancela durante o delay e o `finally` (`:75-81`) nunca manda o relatório zero → Shift/Ctrl/GUI ficam pressionados no PC. Fix: release em `withContext(NonCancellable)`.
- **[Alto] Combos perdem teclas**: só `"DELETE"` é reconhecido em combo (`CTRL ALT DEL` manda só CTRL+ALT); tokens com `length != 1` (`ALT F4`, `CTRL ESC`, `ALT LEFT`) mandam só o modificador (`:157-168`). Fix: tabela única de nomes de tecla.
- **[Médio]** `catch (e: Exception)` engole `CancellationException` (stop vira "Error"); `DEFAULT_DELAY` aplicado a `REM`; comandos desconhecidos (REPEAT, HOLD, MOUSE) ignorados mas "Script finished"; caracteres não-US descartados; stderr do `su` nunca drenado **(possível bloqueio)**; `RootBadUsbScreen` diz "802.11-style keystroke injection"; duas tabelas `charToKeycode` divergentes (a do legado perde `[ ] \ { } ~`).

### 3.7 TOTP, criptografia, relatórios, configurações

- **[Alto] TOTP**: `otpauth://` ignora `algorithm/digits/period` (`TotpViewModel.kt:59-60`) e `TotpGenerator` só faz HmacSHA1 → contas SHA-256/512, 8 dígitos ou 60 s geram códigos errados sem aviso; segredos em texto puro + backup (ver §1); `init { load() }` sem try/catch (JSON corrompido = crash da tela); Base32 inválido é "limpo" silenciosamente (`0,1,8,9` somem); HOTP é anunciado no KDoc mas não existe; label não é URL-decodado; sem `FLAG_SECURE` (códigos/senhas aparecem em screenshots e no recents).
- **[Médio] Password Generator** gera QR da senha na composição com `setPixel` 262 k× na main thread; clipboard sem `EXTRA_IS_SENSITIVE`; sem feedback quando nenhuma classe de caractere está marcada.
- **[Médio] Report Generator**: Markdown não escapa (evidência com ``` fecha o bloco); IDs duplicados após remover (`FINDING-${size+1}`); timeline com `- - `; JSON/HTML omitem a timeline; `average()` de lista vazia → NaN exibido; `java.time` (ver §1).
- **[Médio] Settings**: keep-screen-on só é aplicado enquanto a tela de Settings está composta e `onDispose { }` vazio (não é aplicado no launch, nem limpo ao sair); `notifications/vibration/sound` são persistidos e nunca lidos; KDoc descreve limpeza de cache/export que não existem.
- **[Baixo] CryptoTools**: `isDigit()` aceita dígitos não-ASCII; saída binária de Base64/hex mostrada como U+FFFD; HMAC só com chave UTF-8; `String.format` por byte. `QrScannerScreen` abre URI sem confirmação e perde o resultado na rotação. `colors.xml` com `red_*` alpha 00 (template). Tema pai claro pode piscar branco no dark **(possível)**.
